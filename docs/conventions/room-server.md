# The room server

`src/room/` is the room server for co-op ([../../spec.md](../../spec.md) → Technical architecture): a Cloudflare Worker, and a Durable Object for each room, running the expedition the page runs. The browser's side of it is in `src/page/`: `RoomClient`, and the start's choice that leads there. Both follow [../conventions.md](../conventions.md) → Modules and Objects; these are its own rules.

- **The room is the clock.** While anyone's in, the room steps its expedition twenty times a second, with every player's actions since the last step, and sends each step to every browser (`Room.tick`). A browser takes the room's steps in order and never steps on its own, so every browser shows the same mountain; a step it can't follow drops the connection, for a fresh save.
- **The protocol is `src/room/messages.ts`**: JSON on a WebSocket, every field checked (`Protocol`). In: `hello`, the player's token and the game's version, then `actions`. Out: `welcome`, the room's code, the player's climber and the expedition's save without its log, then a `step` at a time. A refusal is a close code (`CloseCode`): unknown 4404, full 4409, reload 4426, stale 4410, and 4400 for a message that isn't the protocol's. Any other close is a connection lost, which the browser tries again every two seconds.
- **A seat is the player's by their token**, a random one their browser makes and keeps (`PlayerToken`): the same token gets the same climber back, the climbers taken in the scenario's order. An action is always its sender's climber's, whatever the message says. No account, no name.
- **A player who leaves lets go.** At the next step their climber stops where it stands, as the controls do when let go (`LetGo`), so no climber walks on alone. The stop is in the room's save (`RoomSave.queued`): a room the last player left mid-stride, paused before its next step, takes it when it starts again. A climb alone resumed from the device starts the same way (`SoloGame`).
- **The version is checked at the door.** A browser whose build isn't the room's (`hello.version` against the Worker's `GAME_VERSION`) is asked to reload, once (`ReloadOnce`). A page still old after its reload says the game is being updated.
- **A room is never deleted.** It's stored when a player takes a seat, every ten seconds of play, and when the last one leaves (`RoomStorage`: the save under `room`, the log in chunks under `log:`). Then it waits, paused, with its climbers where they were, however long it takes. A room this build can't go on with, saved from before a rule changed, is kept as it is, and whoever comes is told so (`stale`).
- **The Durable Object is a thin shell** (`src/room/worker/`). The Worker routes `/rooms/new` and `/rooms/<code>` (`RoomRoute`), draws a new room's code (`RoomCode`: five characters with no look-alikes), and hands the socket to the room's object. The object holds the sockets, the interval and the storage. Everything decided is in `Room` and `RoomHost`, tested in Node with the fakes of `src/room/testing/`; `e2e/room.spec.ts` runs it all under `wrangler dev`.
- **The room imports the core, the physics and `src/content/`**, through `Mountain`, so its rules and their numbers are the page's: never the page, the input or the rendering, and the page only its protocol and codes. A Worker has no Vite to find the knowledge base's files by a pattern, so `KNOWLEDGE_FILES` names each one, and a test holds the list to the folder.
- **Real time stays in the shell.** `Date.now()` and `setInterval` are the object's (`IntervalTicker`); a tick longer than a second counts as one, so a room back from a stall doesn't race.

`npm run room` serves it on this machine at port 8787, keeping its rooms in `.wrangler/state/`; the page finds it on its own host unless the build is told `VITE_ROOM_SERVER`. The preview's room server and its limits are in [../production.md](../production.md) → The hosting.
