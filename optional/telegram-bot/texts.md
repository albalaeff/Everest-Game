# fxbot conventions: texts

What a change to the texts users read follows, besides what every change does ([docs/conventions.md](../conventions.md)).

## User-facing text

- Every string a user sees goes through an i18n key in the language packs, `fxbot/locales/<code>/*.ftl` (Project Fluent syntax; one folder per pack, `en-US` the base, [docs/translating.md](../translating.md)). Keys exist in **every** pack and use the same `$variables`; `tests/i18n/test_parity.py` enforces this. The code never names a pack: what differs between languages (numbers, units, the language's name, its pictograms, BestChange's site for its readers) is in its `pack.toml` (#330). A pictogram the bot shows on its own is `t.icon("name")`, never a literal in the code; gestures in texts are `{ icon-name }` (`tests/i18n/test_pictograms.py`).
- Look keys up as a string literal: `t.t("quote-posted", id=quote.id)`. The parity test finds keys in code with that pattern, so don't build key names dynamically.
- Key names are kebab-case and start with the feature: `start-welcome`, `quote-preview`, `error-quote-limit`.
- Ukrainian and Russian copy is written as natural Ukrainian and Russian, not word-for-word translation, with correct plural forms (Fluent selectors: `one`, `few`, `many`, `other`). A new message goes into every pack (`en-US`, `uk-UA`, `ru-RU`).
- The bot speaks in the first person singular, in every language: "I keep only the country", "Я не храню ваши деньги", "через меня"; never "we", "our team" (say "the moderators") or "the bot keeps …". In Russian and Ukrainian avoid the past tense with "я", which needs a gender: "Код отправлен", not "Я отправил". Labels about the user ("In the bot since …"), the SMS text (it arrives outside Telegram) and quotes of what other people say are exempt. `tests/i18n/test_voice.py` enforces it.
- A name (`$name`, `$other`) is never declined in Russian or Ukrainian: it reads as its owner typed it. Where the sentence would decline it, the word it hangs on is "собеседник" / "співрозмовник", with the name in brackets ("Жду ответа собеседника ({ $other })", not "Жду ответа { $other }"); elsewhere the name stands on its own ("собеседник: { $name }", "Сделка 5 · { $other } · …"). Nor is anyone's gender guessed: "{ $name }: трансляция выключена", not "выключил(а)". `tests/i18n/test_russian.py` and `test_ukrainian.py` check it (#505).
- An offer or a deal is called by its own number, plainly: "Deal 5", "ID 5 · 1 000 EUR → 100 000 RUB"; never "№5" or "#5", and never a list position as a second number. In lists it reads "ID 5 · …", so it's clear what the number is. An offer's amounts read "X → Y" (what the poster gives → gets), not "sells X for Y". Facts on one line are separated by " | " (`fxbot.bot.formatting.SEPARATOR`).
- The two sides of an exchange are what one **gives** and what one **gets** (ru *отдаёте / получаете*, uk *віддаєте / отримуєте*), given first: never buy and sell, nor pay, in any language. Something is bought only with Telegram Stars (⭐ VIP). `tests/i18n/test_give_get.py` enforces it; the Stars texts are its only exceptions (#311).
- A city a user typed is stored through `fxbot.domain.cities.resolve_city(country, text)` and shown through `city_name(country, city, language)` (in a queued notification: a `Place` param), never as stored: a known city then reads in the reader's language.
- Format numbers, money and dates in Python and pass them to Fluent as strings.
- Messages are sent with HTML parse mode, so user-provided text (names, notes) inserted into them is escaped with `html.escape(..., quote=False)`.
- After changing an English text, run `uv run python scripts/build_screen_map.py`: [docs/screen-map.html](../screen-map.html) shows a sample of each screen, and a test fails while it's out of date ([bot.md](bot.md) → Screen IDs).
